# STEMCare Pre-Consultation Demo — Partner Test Guide

For design-partner testing (360medicx). This document states what the demo
is, what it deliberately is not, and a structured pass/fail script. Anything
that fails a numbered case below is a bug; anything in **Known limitations**
is by design.

This standalone deployment serves the demo at the site root (`/`); the
marketing landing page lives at https://stemcare.co.uk/ and the header's
"Back to Home" button navigates there.

## What this demo is

- A simulation of STEMCare's pre-consultation intake workflow: structured
  interview → NHS red-flag gate → live clinical briefing → differential
  hypotheses → clinician authorization gate.
- **Two runtime modes:**
  - **Deterministic (default):** the interview follows the same
    deterministic question-policy engine as the production system. Every
    behavior is reproducible and nothing typed leaves the browser.
  - **Live model (opt-in):** when the deployment enables it (see below),
    responses are generated by Google's Gemini through a **server-side
    proxy** (`/api/gemini`). The API key never reaches the browser, prompts
    are built server-side, every model response passes the assistive-only
    policy gate on the server *and* the client, and any failure falls back
    silently to the deterministic engine. One nuance: once a live briefing
    has been produced, an isolated live-report failure keeps the existing
    live briefing for that turn (the newest answer syncs on the next
    successful update) rather than visibly downgrading it mid-interview.
    In this mode text you type is sent to our server and processed by Google.
- **No persistence.** Nothing typed is stored anywhere; closing the tab
  discards everything.

## What this demo is not

- Not medical advice and not a clinical service. It is a sales/demo surface.
- Not the production accuracy story: STEMCare makes no accuracy claims for
  its AI until a measured evaluation run passes. Probability labels in the
  demo are **illustrative ranking buckets**, not calibrated estimates.
- Not the production safety stack in full: the demo ports the red-flag
  detector and the assistive-only output policy; the server-side Guardian
  layer, audit receipts, and clinician-review persistence live in the
  production app and are represented here as simulated UI.

## Automated evidence

`npm test` runs the full suite (deterministic engines, live-engine gating
with mocked model responses, red-flag coverage, per-scenario autoplay
rehearsals, markdown XSS hardening). Partners are welcome to run it.

## Live model mode (for clinicians)

The deterministic demo shows the workflow; live mode shows the model. To
enable it on a deployment:

1. `VITE_DEMO_LIVE_MODE="true"` (client flag)
2. `GEMINI_API_KEY="<server-side key>"` (Vercel env — **never** `VITE_`-prefixed)
3. Optional: `DEMO_GEMINI_MODEL` (default `gemini-3.1-flash-lite`, matching
   production model policy) and `DEMO_LIVE_KILL_SWITCH="true"` to force
   deterministic fallback instantly.

What changes under live mode — test these specifically:

- The header pill reads **"Live model · Server-proxied"** and the banner
  discloses that input is processed by Google's Gemini.
- Interviewer questions are model-generated but still enforced to ONE
  question, ≤20 words, no preamble, no diagnosis (try to bait it: mention
  chest pain, ask "what do you think it is?", answer nonsense — the
  interviewer must stay a short fact-finding question regardless).
- The briefing updates via the report-writer persona; it may rephrase
  freely but must not assert diagnoses or prescribing directives (gated).
- Differentials may cite model-generated hypotheses; any card drifting into
  definitive-diagnosis or prescribing language gets its action text replaced
  with an abstention notice (server-side, before the client sees it).
- The red-flag gate remains LOCAL and deterministic — emergency phrases
  terminate the interview before any model call.
- Kill-switch/permissioning check: network failures, rate limits, or the
  kill switch degrade the demo to deterministic mode — it should never
  break or show an error mid-interview.
- Privacy trade-off is real in this mode: input is processed by a
  third-party AI provider. Do not enter real patient data.

## Manual test script

Run `npm run dev` (or the deployed root URL). Each case: **action →
expected result**.

1. **Launch** — Load the site → demo loads with a persistent notice banner;
   migraine scenario pre-selected; chat shows the canonical NHS greeting.
2. **Tour** — Open "60s Tour" → four slides; no accuracy/calibration/
   compliance claims; Escape and arrow keys work.
3. **Curated autoplay** — Press "Auto-Play Case" → interview proceeds one
   question per turn (~13 turns: core HPI plus the full history block),
   no repeated identical questions, ends with the completion phrase (no
   "End interview." marker visible); briefing updates each turn and every
   finding cites its source chat line.
4. **Handoff** — After completion → a small card fades in at the bottom
   left 5 seconds later: "Consultation finished … ready for review." with
   "Open review" and "Later". Open review switches to the focused review;
   Later dismisses. The Review tab remains as the fallback entry.
5. **Review** — The review is short and cited: a "From the chat" card lists
   the key findings, each with a citation chip (hover shows the verbatim
   chat line, click jumps to the message); below it, "Here's what I
   concluded we should do:" states the suggested triage with its reason.
6. **Approve / Edit** — Approve signs the suggested triage immediately
   (receipt card with Modify). Edit drops down the other dispositions;
   picking one and authorizing records the edit ("Edited from the
   suggested …"). Authorize stays disabled until a disposition is picked.
7. **Custom case** — Switch to "Fresh Start (Custom Case)" → a details card
   asks for name, age, and sex (all optional; blanks render as "not
   provided" in the report rather than a fictional identity) → start the
   interview → type any symptom narrative → interview asks varied,
   non-repeated questions, always covers onset, severity, modifiers, past
   conditions, medications, allergies, and family/social history before it
   may end, and terminates within ~15 questions; briefing Chief Complaint
   stays fixed on the FIRST message and does not drift to later messages.
8. **Wrap-Up Intake** — "Wrap-Up Intake" appears after 2+ answers but stays
   disabled (with an explanatory tooltip) until the history block and HPI
   core have been asked. After the gate is satisfied → click it → no blank
   patient bubble appears; interview concludes; differentials generate.
9. **999 red flag** — Type "I want to kill myself" → interview halts
   immediately, 999 + Samaritans (116 123) guidance shown, differentials tab
   shows "Differential Generation Blocked", clinician gate offers emergency
   escalation.
10. **111 red flag** — Type "I have chest pain" → 111 guidance (not 999);
    "chest pain and sweating" → 999. Interview terminated either way.
11. **Negation** — Type "I have a cough but no chest pain" → NO emergency
    banner; interview continues normally.
12. **Same-day routing** — Malaria scenario autoplay (travel + rigors) →
    completes; the malaria rule routes to same-day GP wording when triggered.
13. **XSS attempt** — Type `<img src=x onerror=alert(1)>` → text renders as
    inert text in chat; check the Clinical Briefing: no script executes, no
    event handlers in the rendered HTML.
14. **Long input** — Paste 500+ characters → input caps at 500 characters.
15. **Rapid interaction** — Double-click send, click chips during
    "Synthesizing…", switch scenario mid-turn, hit Reset mid-turn → no
    duplicated messages, no stale scenario content bleeding into the new
    session, no mixed state.
16. **Scenario switch** — Switch between all four cases and Custom → chat,
    briefing, differentials, and clinician gate all reset cleanly.
17. **Refresh** — Refresh the page → demo reloads directly with the
    deterministic greeting. "Back to Home" navigates to the STEMCare
    landing site (https://stemcare.co.uk/).
18. **Mobile layout** — Narrow viewport → tab switcher (Chat / Briefing /
    Review) works; banner remains readable.
19. **Theme** — Light/dark toggle works and persists across reloads.
20. **Privacy (deterministic mode)** — Open browser DevTools Network tab;
    interact freely → zero requests fire while typing/sending (only static
    asset loads at startup). In live mode, the only requests are to
    `/api/gemini` on the same origin — never to a model provider host.
21. **Report citations** — After a few interview turns, HPI/history bullets in
    the Clinical Briefing end with small numbered chips (in BOTH modes: the
    deterministic engine knows the exact source line of every finding).
    Hovering a chip shows the verbatim patient line it was paraphrased from;
    clicking it (or focusing it and pressing Enter) switches to the Chat tab,
    scrolls to the source message, and flashes it. Chips must never appear
    for clinician lines, and each finding carries exactly one citation even
    if the same words appear twice in the chat.

## Known limitations (by design — not bugs)

- The patient simulator is a scripted roleplay reasoner; its answers are
  canned per condition and vary only by symptom selection. Two autoplay runs
  share the same answer style.
- The interviewer's questions come from a fixed policy table (one per
  topic); wording is generic, not complaint-specific.
- Negation handling is clause-scoped with a 50-character window; unusual
  phrasings (e.g. "chestpain" without a space) will not match.
- Red-flag guidance in a *demo* is deliberately over-cautious: any affirmed
  emergency phrase ends the interview with escalation advice.
- The demo contains no persistence: reviews, reports, and sessions are lost
  on reload. The production system persists receipts and audit events.

## Reporting issues

Note the case number above, the scenario, the exact input, and a screenshot.
Bugs that break a numbered case are release blockers; new-content suggestions
(scenario ideas, wording) are tracked separately from safety fixes.
