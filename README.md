# STEMCare Demo

Standalone deployment of the STEMCare pre-consultation demo (the MedGemma
demo), extracted from the [STEMCare-Landing](https://github.com/M-priv/STEMCare-Landing)
repository so it can ship on its own domain independent of the marketing site.

The demo simulates STEMCare's pre-consultation intake workflow: structured
interview → NHS red-flag gate → live clinical briefing → differential
hypotheses → clinician authorization gate. It is a sales/demo surface — not
medical advice and not a clinical service. See `DEMO_TESTING.md` for the full
partner test guide.

## Two runtime modes

- **Deterministic (default):** every response comes from the deterministic
  policy engines ported from the production system. Nothing typed leaves the
  browser; zero network requests fire during a session.
- **Live model (opt-in):** responses are generated by Google's Gemini through
  a server-side proxy (`/api/gemini`). The API key never reaches the browser,
  every model response passes the assistive-only policy gate on the server and
  the client, and any failure falls back silently to the deterministic engine.
  In this mode, text you type is sent to our server and processed by Google —
  do not enter real patient data.

## Run locally

```bash
npm install
npm run dev
```

`npm test` runs the full suite (deterministic engines, live-engine gating
with mocked model responses, red-flag coverage, per-scenario autoplay
rehearsals, markdown XSS hardening).

### Live model mode locally

`npm run dev` serves the live path too: a dev-only middleware in
`vite.config.ts` mirrors the Vercel function at `/api/gemini`. Put your key
in `.env` (git-ignored — never commit it):

```
VITE_DEMO_LIVE_MODE="true"
GEMINI_API_KEY="<your key from aistudio.google.com>"
```

Then run `npm run dev` and pick a scenario — the header pill should read
"Live model · Server-proxied". Without a key the endpoint answers
`{"fallback":true,"reason":"not_configured"}` and the demo stays
deterministic; a rejected key answers `model_unavailable`.

## Deploy (Vercel)

Import this repository in Vercel with:

- Framework preset: `Vite`
- Build command: `npm run build`
- Output directory: `dist`

The `api/gemini.js` function (bundled from `src/server/gemini.ts`) is auto-detected as a serverless function; the
SPA fallback rewrite lives in `vercel.json`.

### Enabling live model mode

Set these environment variables on the deployment (all optional):

| Variable | Scope | Effect |
| --- | --- | --- |
| `VITE_DEMO_LIVE_MODE="true"` | build (client) | Enables `/api/gemini` calls; safe to expose |
| `GEMINI_API_KEY` | server only | Server-side Gemini key — **never** `VITE_`-prefixed |
| `DEMO_GEMINI_MODEL` | server only | Model override (default `gemini-3.1-flash-lite`) |
| `DEMO_LIVE_KILL_SWITCH="true"` | server only | Forces deterministic fallback instantly, no redeploy |

Without the key or with the kill switch set, the demo runs fully
deterministic and never contacts a model provider.

## Relationship to STEMCare-Landing

This repo carries the demo (`src/demo/**` and `api/gemini.js` bundled from `src/server/gemini.ts`).
The landing repository remains the marketing site and the
upstream source for the demo code; `src/demo.css` here is an extraction of
the demo styles from the landing's `App.css` (tokens + base typography + the
full demo section). If the design system or demo engines change upstream,
re-port them here.

The header's "Back to Home" button navigates to `https://stemcare.co.uk/`.
